# Работы по юнитам

Здесь восемь папок по разделам *Mindset for IELTS*, Level 3. В каждой есть `reading/`, `writing/`, `listening/`, `speaking/` и `academic/` для ваших работ. В `README.md` конкретного юнита указаны страницы учебника и результат для academic English.

Грамматику ведём отдельно по общим темам в [`../grammar/`](../grammar/README.md), с собственным журналом проверок. Ошибки из работ любого юнита используем для выбора следующей грамматической подтемы.

Слова и выражения из всех юнитов собираем в общем [`../vocabulary/`](../vocabulary/README.md). Во время задания можно написать «в словарь: …» или `[vocab: phrase]`; преподаватель также фиксирует замеченные трудности употребления. Словарные повторения имеют собственный журнал.

## Как называть файлы

Формат: `ГГГГ-ММ-ДД-задание-attemptN.расширение`. Например:

- `units/01-urban-and-rural-life/writing/2026-10-20-task1-attempt1.md`
- `units/01-urban-and-rural-life/writing/2026-10-22-task1-attempt2.md`
- `units/01-urban-and-rural-life/speaking/2026-10-20-part2-attempt1.m4a`

Исправленный вариант храните отдельным файлом, чтобы было видно изменение. Для Writing полезно записать в начале файла точное задание, отведённое время, черновик и замечания репетитора. Для Reading/Listening сохраняйте ответы **до** проверки и разбор ошибок после неё.

## Summary, recap и отчёт преподавателю

После завершения каждого раздела Reading / Writing / Listening / Speaking / Academic сохраняем в его папке два файла: `YYYY-MM-DD-summary.md` и `YYYY-MM-DD-teacher-report.md`. После всего юнита делаем общий итог в папке юнита. Ссылки на готовые итоги находятся в README юнита. Правило для будущих учебных чатов закреплено в [`../AGENTS.md`](../AGENTS.md).

В summary фиксируем материал, реальные результаты, сильные стороны, трудности с примерами и 2–3 приоритета повторения. Отдельно отмечаем работу после подсказок и то, что ещё предстоит проверить на новом тексте. Добавляем короткий recap на следующее занятие и отсроченную проверку. В мини-отчёте для преподавателя оставляем результат, наблюдения и конкретную задачу на занятие. Эти файлы не считаются новыми попытками в журнале; запланированные проверки записываем только после выполнения.

## Журнал для графиков

Все попытки вносите в [`progress.csv`](progress.csv). **Одна строка — одна выполненная попытка или проверенная работа.** Неизвестные время и оценки оставляем пустыми; результаты не придумываем.

| Колонка | Значение |
| --- | --- |
| `date` | Дата в формате `YYYY-MM-DD`. |
| `unit` | Номер `01`–`08`; для диагностического теста вне юнитов — `diagnostic`. |
| `skill` | `reading`, `writing`, `listening`, `speaking` или `academic`. |
| `task` | Короткое имя: `matching-headings`, `task1`, `task2`, `part2`, `paper-summary` и т. п. |
| `attempt` | Номер попытки **того же задания**: 1, 2, 3… |
| `minutes` | Фактически затраченное время. |
| `correct`, `total` | Число правильных ответов и число вопросов для Reading/Listening; оставить пустыми для текстов и речи. Процент затем считается как `correct / total × 100`. |
| `band_estimate` | Осторожная оценка Writing/Speaking по критериям от репетитора или пробного экзамена; для официального результата можно записать официальный band. Не смешивать самооценку и оценку преподавателя в одном графике без пометки в `notes`. |
| `word_count` | Объём письменной работы в словах; для других навыков пусто. |
| `work_file` | Путь к файлу **от корня репозитория**, например `units/01-urban-and-rural-life/writing/2026-10-20-task1-attempt1.md`. |
| `notes` | Причина ошибки, источник оценки, следующий шаг. Если есть запятые, заключить значение в двойные кавычки. |

Для графика Reading/Listening сравнивайте процент правильных ответов **при одинаковых условиях времени и сопоставимых заданиях**. Writing и Speaking показывайте отдельными линиями по оценке критериев, а не объединяйте с процентом правильных ответов. Время занятий можно построить отдельным графиком по `minutes`. Разные задания имеют разную сложность, поэтому один резкий скачок не означает устойчивый рост; сравнивайте несколько попыток и полные пробные тесты.

Пустые подпапки сохраняются в Git с помощью `.gitkeep`; их можно оставлять рядом со своими файлами.
